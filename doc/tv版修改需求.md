# TV 版 UI 改造需求文档

> 版本：v1.0 ｜ 状态：待评审 ｜ 最后更新：2026-11-04

## 1. 背景与目标

LibreTV 安卓电视版（包名 `com.srctv.apptv`）本质是一个 **Android WebView 壳**（`android/app/.../MainActivity.kt`），壳内加载 Web 站点（当前 `START_URL = https://srctv.xyza.workers.dev`），所有业务逻辑（搜索、播放、源管理、订阅同步）都在 Web 端（Next.js + React）。

**现状问题**：Web 端是为鼠标/触屏设计的，遥控器（D-pad）操作体验差：
- 现有壳注入的 `injectTvNav`（`MainActivity.kt:297`）是「全页可交互元素一维线性循环」，没有空间方位概念；
- 弹窗 / 二级界面打开后焦点仍停留在底层，导致「二级界面点不到」；
- 缺少 TV 惯有的焦点放大、横向焦点行等观感。

**目标**：在 **TS/Web 层**完成 TV 交互适配，使遥控器可完整操控主链路（搜索 → 结果 → 播放）及设置等二级界面，达到「真实可用」的 TV 体验，**不新建 Android 原生工程**。

---

## 2. 架构决策

| 选项 | 结论 |
|---|---|
| 新建 Android TV 原生工程（Kotlin/Leanback） | ❌ 否。业务逻辑全在 TS/后端，原生重写工作量是数倍且长期双端维护不同步 |
| **在 TS 层做 TV 适配** | ✅ 是。复用全部业务逻辑与后端代理，一次改动两端（网页/APK）受益 |

**关键原则**：
- TV 适配逻辑全部落在 Web 端 TS/TSX，壳只负责「告诉 Web 当前是 TV」与「转发遥控器按键为键盘方向键」（后者 `injectTvNav` 已部分实现，后续可弱化/移除）。
- Web 端浏览器打开时**完全不受影响**（通过 TV 模式标志隔离）。
- 焦点引擎用 **DOM 空间几何**做导航，而非线性列表。

---

## 3. 总体方案

1. **TV 模式识别**：壳注入 `window.__TV__ = true`（tv flavor 下），或在 URL 带 `?tv=1`、localStorage 持久化标志。Web 端读取该标志决定是否启用 TV 布局与焦点引擎。
2. **焦点引擎**（`tv-focus.ts` 新模块）：监听 `keydown` 的 Arrow/Enter/Backspace，基于元素屏幕几何中心做「向某方向找最近可见可交互元素」的空间导航；按 TV 标志全局启用。
3. **焦点可视态**（CSS）：`:focus-visible` / 自定义焦点类做放大 + 高亮描边，替代鼠标 hover。
4. **TV 布局**：首页/搜索结果改为横向焦点行（Leanback 风格），顶部导航纳入焦点系统；设置弹窗焦点 trap。
5. **播放页 TV 操作**：D-pad 左右 seek、上下换集、确认暂停/播放。

## 3.1 布局隔离原则（硬约束）

TV 适配**不得**以「在现有网页业务组件内散布 `if (isTv)` 条件分支」的方式实现。必须采用分层隔离，保证网页版零回归且 TV 代码可维护。所有 TV 落地方式（见开发进度文档 M1~M2）均须遵守：

- **逻辑层复用**：搜索、播放器、store、订阅同步等业务逻辑**完全复用、零改动、不感知 TV 存在**。TV 与网页仅通过「页面/布局容器」组合不同，而非修改业务组件内部。
- **布局层抽离**：将「导航骨架 / 页面容器」做成可插拔的布局组件。同一业务页面（如搜索结果、播放页）在 TV 模式下套 `Tv*Layout`、网页模式套原 `Layout`；业务子组件作为 children 塞入对应布局。焦点引擎只挂在 TV 布局层。
- **样式层隔离**：所有 TV 专属样式挂在根节点 `.tv-mode` class 作用域下，**物理隔离**于网页 Tailwind 类；focus 态与 hover 态互不干扰，禁止在业务组件上直接加 TV 样式类。
- **TV 代码集中**：TV 相关实现集中在 `tv-*` 模块 / `components/tv/*` 组件下；业务组件通过 props 或布局组件注入接收 TV 行为，自身不含 TV 分支。
- **渐进式落地**：先以最小改动让焦点引擎 + focus trap 套在现有页面（M1，不改布局），再针对最碍眼页面做 TV 专属布局替换（M2），不一次性推倒重来。

## 4. 功能需求（FR）

### FR-1 TV 模式识别与切换
- **FR-1.1** 壳（`MainActivity.kt`）在 `onCreate`/页面加载时注入 `window.__TV__ = true`，且 `BuildConfig.FLAVOR == "tv"` 时注入。
- **FR-1.2** Web 端提供 TV 模式判定入口（如 `isTvMode()`），读取 `window.__TV__`；浏览器地址带 `?tv=1` 时强制开启，便于桌面调试。
- **FR-1.3** TV 模式下不破坏网页版默认交互（鼠标/触屏照常）。

### FR-2 空间焦点引擎
- **FR-2.1** 监听方向键（ArrowUp/Down/Left/Right），从当前焦点元素出发，在**可见**的可交互元素集合中，按「候选元素中心落在按键方向的扇形/象限内 + 距离最近」选取下一个焦点（替代现有线性循环）。
- **FR-2.2** 焦点元素集合覆盖：`<a>`、`<button>`（非 disabled）、`<input>/<textarea>/<select>`（非 disabled）、`[role="button"]`、`[tabindex]` 且可见。
- **FR-2.3** 输入框聚焦时**不拦截**方向键，保证正常输入；Enter 触发确认（click）。
- **FR-2.4** 页面加载/路由变化后，自动把焦点落到当前视图第一个可交互元素；视口滚动时把焦点元素滚动进可视区域。
- **FR-2.5** 现有壳 `injectTvNav` 的线性逻辑在 TV 模式下**停用**，避免两套导航冲突（移动端壳行为不变）。

### FR-3 焦点可视态（TV 观感）
- **FR-3.1** 全局定义 TV 焦点样式：放大（transform scale 1.05~1.1）+ 高亮描边（盒阴影/边框），过渡动画平滑。
- **FR-3.2** 焦点态仅在 TV 模式生效，不影响网页 hover 样式。
- **FR-3.3** 焦点态对卡片、按钮、列表项、输入框统一表现。

### FR-4 弹窗 / Modal 焦点陷阱（Focus Trap）
- **FR-4.1** 任意 Modal/Dialog/抽屉打开时，焦点引擎将候选范围**限定在弹窗内部**，Tab/方向键在内部循环，不逃逸到底层页面。
- **FR-4.2** 弹窗关闭后，焦点**归还**到触发元素（或上一焦点）。
- **FR-4.3** 解决现状核心痛点：设置、源管理、确认框等二级界面可用遥控器完整操作（包括关闭）。
- **FR-4.4** 提供统一的 Modal 容器/包裹组件，自动接入 focus trap，避免每个弹窗各写一套。

### FR-5 TV 布局适配
- **FR-5.1** 首页改为横向焦点行（分类/推荐一行，左右移动切换、上下换行），卡片获得焦点时放大。
- **FR-5.2** 顶部导航栏（搜索框、设置入口）纳入焦点系统，方向键可达。
- **FR-5.3** 搜索结果页：结果卡片网格/横向行支持 D-pad 导航与焦点态。
- **FR-5.4** 设置/源管理页：在 TV 模式下布局放大、间距适配远距离观看，保持全功能可达。

### FR-6 返回与导航
- **FR-6.1** 遥控器「返回键」：弹窗打开时先关闭弹窗；否则触发页面路由后退。实现机制（M4 落地）：Android 返回键不会以 keydown 形式派发给网页，故由壳 `MainActivity.kt` 的 `handleOnBackPressed`（TV 风味）先 `evaluateJavascript` 调网页注册的 `window.__srctvConsumeBack`；网页端 `closeTopModal()` 关闭最上层弹窗（`role="dialog"/"alertdialog"/aria-modal="true"/data-tv-trap`，命中各弹窗自带关闭逻辑，兜底点关闭按钮/全屏遮罩）并返回 true 消费返回；无弹窗则返回 false。
- **FR-6.2** 页面内未消费返回键时，壳回退 WebView 历史（`webView.goBack()`，对 SPA 即客户端路由后退）；无可回退历史则 `finish()` 退出应用。移动端风味保持原直接 `goBack/finish` 行为。

### FR-7 播放页 TV 操作
- **FR-7.1** 播放页监听方向键：进入播放页自动聚焦**可见播放控制条**（底部工具条，FR-7.2 落地）；←/→ 在控制条按钮间导航（快退/上一集/播放暂停/下一集/快进/全屏），Enter/空格 触发当前高亮按钮；↑/↓ = 上一集/下一集（如有多集，受 `hasPrev/hasNext` 约束）。seek（快退/快进 ±10 秒，常量见 `useTvPlayerControls` 的 `SEEK_STEP`）改为点对应按钮触发。剧集列表亦可在退出控制模式（Esc）后方向键导航 + 确认选集（见 M3-3）。
- **FR-7.2** 播放控制条焦点可见；全屏切换（壳已支持 `CustomView`）遥控器可达。实现机制（M3-4 落地 + M4-3 真机联调修正）：控制层改为可见工具条，当前高亮按钮用 `.tv-focused`（绿描边）标记 → 焦点可见（10-foot UI）；工具条含「全屏切换」按钮，`PlayerSkipApi` 新增 `toggleFullscreen()`，遥控器 ←/→ 导航到该按钮、Enter 触发即可全屏。**全屏实现按环境分流（M4-3 联调定稿）**：Android WebView 静默拒绝容器 div 的 Element Fullscreen API（`onShowCustomView` 不触发），且 ArtPlayer `fullscreen` setter 被拒后状态乐观置位，故不再「先试原生再读回」——有 `SrctvBridge`（Android 壳）时直接走 ArtPlayer `fullscreenWeb`（CSS 网页全屏）+ `html.tv-web-fs` 类（控制层提升 fixed 覆盖，全屏态控制条仍可遥控）+ 壳 `SrctvBridge.toggleImmersive()` 沉浸式（`WindowInsetsControllerCompat` 隐藏系统栏）；无 bridge（桌面调试）走原生 fullscreen（与 `f` 键一致）。退出时还原全部全屏态。另：播放页进入时焦点锁定在控制条（每 800ms 夺回）直到用户首次按键或 Esc 退出，防止加载期动态元素抢焦致遥控误触（M4-3 联调发现）；TV 模式下「下载本集」按钮 `data-tv-hide` 隐藏（TV 不支持下载且其提示 toast 会抢焦点）。
- **FR-7.3** 不与 FR-2 通用焦点导航冲突：播放页进入「控制模式」时方向键优先控制播放器（焦点引擎对 `data-tv-player-control` 豁免）；按钮不抢真实焦点，焦点始终在控制层自身。

### FR-8 TV 模式功能屏蔽（2026-11-04 追加）
- **FR-8.1** 顶栏「下载管理」入口在 TV 模式下**不显示**：下载依赖鼠标/长按交互，遥控器场景用不上。
- **FR-8.2** 顶栏「设置」入口在 TV 模式下**不显示**：设置页表单密集，不适合远距离遥控操作（未来落地 TV 专属设置页后再评估放开）。
- **FR-8.3** 实现方式遵守 §3.1：业务组件仅挂惰性 `data-tv-hide` 标记（零逻辑分支），隐藏规则集中在 `.tv-mode` 作用域 CSS（`components/tv/tv.css`）；网页模式不含 `.tv-mode`，标记无任何效果。`display:none` 元素天然被焦点引擎的可见性过滤排除。

### FR-9 TV 搜索文字输入（2026-11-04 追加，对应 M5）
- **FR-9.1** TV 模式搜索框获得焦点时，**自动弹出网页自绘虚拟键盘**（QWERTY 字母 + 数字 + 空格/删除/清空/搜索），方向键选键、确认键落字，解决「遥控器无法在原生输入框打字」问题；网页模式不弹，保持原生输入。
- **FR-9.2** 虚拟键盘为英文/数字主链路：可输入字母、数字、空格，覆盖英文名 / 拼音串 / 数字搜索场景；**不内置拼音/中文 IME**（中文输入由 FR-9.3 的语音承担）。
- **FR-9.3** TV 模式搜索框提供**语音输入入口**（麦克风按钮）：由原生 Android `SpeechRecognizer` 识别，识别文字注入搜索框，负责中文输入。无麦 / 不支持 / 权限被拒时，麦克风按钮禁用或给出轻提示，不阻断键盘输入。
- **FR-9.4** 实现遵守 §3.1：Web 侧仅挂覆盖层 + 受控组件（业务搜索框零 TV 分支）；原生仅新增桥方法 + `RECORD_AUDIO` 权限（麦克风特性 `required=false`，无麦设备不崩溃）。

## 5. 非功能需求（NFR）

- **NFR-1** 性能：焦点计算在全页元素规模下 < 16ms/次，低端电视盒子流畅。
- **NFR-2** 兼容性：TV 模式在 Android WebView（壳）与桌面 Chrome（调试）行为一致。
- **NFR-3** 可调试：桌面浏览器通过键盘方向键即可完整模拟 TV 操作，无需每次打包 APK。
- **NFR-4** 零回归：网页版（非 TV 模式）功能与样式不变。

---

## 6. 验收标准

1. 遥控器（或桌面方向键）可在 TV 模式下完成：打开 App → 焦点落在首页首元素 → 切换到搜索并输入 → 进入结果 → 选片 → 进入播放并可 seek/暂停 → 返回。
2. 设置、源管理、确认弹窗等二级界面**全部可用遥控器打开、操作、关闭**，焦点不丢失、不逃逸。
3. 焦点元素有清晰放大/高亮可视态，符合 TV 观看距离习惯。
4. 网页版（不带 `?tv=1`、非 TV 壳）交互与样式无回归。
5. 桌面浏览器用键盘即可复现全部 TV 操作，便于验收。

## 7. 范围边界

**In Scope**
- Web 端 TS/TSX 层 TV 适配（焦点引擎、布局、播放控制）。
- 壳最小改动（仅加 `window.__TV__` 注入、停用旧线性导航）。
- 遵循 §3.1 布局隔离硬约束：逻辑复用、布局抽离、样式隔离、TV 代码集中。

**Out of Scope**
- 不重写 Android 原生 UI（不新建工程、不用 Leanback/Compose）。
- 不改动后端 / 视频代理逻辑。
- 不处理域名/网络可达性问题（workers.dev 被墙等属部署侧，见其他讨论）。
- 不新增播放器内核（沿用现有 Web 播放方案）。
- 不在业务组件中散弹式 `if (isTv)` 打补丁式的 TV 适配（违反 §3.1）。
