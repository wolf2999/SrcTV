# TV 版真机待测项

> 说明：TV 版大量功能依赖 Android TV / 电视盒子的**系统 WebView**（非桌面浏览器）。
> 以下问题只能在带 WebView 的真机/盒子上验证，桌面浏览器 `?tv=1` 或模拟器无法覆盖：
> - TV WebView 拒绝 `Element.requestFullscreen`，全屏走 CSS 降级路径（桌面走真实全屏，复现不到真机路径）；
> - 语音识别依赖设备自带**语音引擎**（通常需 GMS），模拟器无麦无引擎，无法测；
> - 外网拉流（直播/点播）在 AVD 上慢/失败，未真机验证；
> - 遥控器键码、返回键、沉浸模式等系统交互必须原生 + 真机。
>
> 标注「已真机联调」表示 M4-3 阶段做过一次，仍建议在不同盒子上复验（各盒子 WebView 版本/键码有差异）。

## 一、必须真机才能验证（模拟器/桌面不可复现）

### 1. 语音输入搜索（M5）
- 依赖设备自带语音识别引擎（通常需 GMS / Google 语音）。无 GMS 的国产盒子即使有麦，也可能 `isRecognitionAvailable=false`，麦克风按钮直接置灰。
- 需逐一验证四个错误分支的飘字提示（见 `TvKeyboard.tsx` 的 `voiceStatusToMsg`）：
  - `unavailable`（无语音引擎）：飘字「设备不支持语音输入」，提示改用键盘；
  - `permission-denied`（麦权限被拒）：飘字「麦克风权限被拒绝」，提示去系统设置开启；
  - `no-speech`（识别窗口无有效语音）：飘字「没听清」；
  - `error`（引擎异常）：飘字「语音识别失败」。
- 正常链路：带麦真机说出中文片名 → 识别文字落入搜索框 → 约 400ms 后**自动发起搜索**并关闭键盘、跳结果页（需确认搜的是识别后的值，非旧值）。
- 验证要点：中文识别准确率、自动搜索是否正确触发、飘字约 3.5s 自动消失、新错误重置计时不堆叠。

### 2. 真机全屏（CSS 网页全屏降级）
- TV WebView 拒绝 `Element.requestFullscreen`，已降级为 CSS 网页全屏（`.tv-web-fs`）。桌面浏览器走真实全屏 API，复现不到真机降级路径。
- 验证：进入播放 → 全屏 → 退出；确认无黑边/无错位、控制条「重新进入」悬浮入口位置正确、播放区占满屏幕。

### 3. 沉浸模式（Immersive）
- `toggleImmersive` 经原生 `hideSystemUi` 隐藏系统导航栏/状态栏，必须原生 + 真机。
- 验证：播放页切换沉浸，系统栏隐藏/恢复，且不影响 D-pad 操作与返回键逐级退出。

### 4. 遥控器键码与返回键（各盒子差异）
- 不同盒子 KEYCODE / D-pad 行为不同。`setTVMode` 的全局 `onKeyDown` 监听、返回键拦截（`preventDefault`）需多盒子验证。
- 验证：方向键焦点移动顺序、OK 确认、返回键逐级退出（播放 → 键盘/详情 → 列表）、长按重复速率。

## 二、建议真机复验（桌面可跑但行为/渲染可能不同）

### 5. 外网流播放（直播 / 点播）
- AVD 外网拉流慢/失败，直播/点播真实起播、清晰度切换、缓冲未真机验证。
- 验证：点播一部片并切换清晰度；直播 M3U 解析并起播；卡顿/缓冲/错误提示是否合理。

### 6. WebView 渲染差异
- `inset` 描边、`::before` 伪元素边框、`:focus` 描边在老版本 Android WebView 上可能不支持/表现不同（进度文档已注明建议真机复验）。
- 验证：卡片焦点高亮可见、键盘按键边框、播放控制条布局在各版本 WebView 无错位。

### 7. 自动播放策略
- 部分 WebView / 盒子禁止无手势自动播放。验证点播点击后是否自动起播，否则需降级为「点击播放」。

### 8. 原生桥 SrctvBridge 全量接口
- `dispatch` 双向桥、webSearch/webDetail/webQuality/webProxy、cookie 透传会话，需真机验证端到端（桌面无 SrctvBridge，走 fetch 兜底路径）。
